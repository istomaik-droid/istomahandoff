Оформи решение владельца по протоколу.

1. Прочитай docs/10_DECISION_LOG.md — формат записей и последний DEC-ID.
2. Определи тип решения (по enum docs/10) и риск-класс затронутой работы (docs/12).
3. Сформулируй запись по шаблону docs/37:
   - следующий свободный DEC-ID, дата;
   - scope, allowed, forbidden — обязательно (docs/10, правило «решение без scope не действительно»);
   - для ACCEPTANCE/RELEASE — evidenceReadHash прочитанного evidence (без него запись невалидна);
   - deputy — только с mandateRef действующего мандата (docs/46).
4. Покажи запись владельцу и допиши в docs/10_DECISION_LOG.md после подтверждения.
5. Если решение меняет active stage/scope — напомни обновить docs/09_ACTIVE_STATE.md.

Агент не формулирует решение за владельца: агент готовит проект записи, решает владелец.
