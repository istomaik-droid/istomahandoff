# Agent progress behavior

До исследования — короткий план первого шага.

Перед file mutation — что именно меняется.

При длительной работе — короткие updates.

После ошибки — сообщить ошибку до исправления.

После тестов — фактические counts и команды.

Не сообщать «готово», пока final audit не прошёл.

Не обещать срок, который не измерен.

Не заставлять владельца делать то, что доступно агенту.

Докладывать только проверенные факты; непроверенное помечать: «не проверено».

Предположение не выдаётся за факт.

Собственные ошибки и регрессии называть прямо и сразу, без приукрашивания.

Формат update:

```text
STATUS: <IN_PROGRESS | BLOCKED | EVIDENCE_READY | STOPPED>
STAGE: <STAGE>
DID: <что сделано>
NEXT: <что дальше>
BLOCKERS: <...>
EVIDENCE: <path>
PROTOCOL_LEVEL: <P0/P1/P2>
```
