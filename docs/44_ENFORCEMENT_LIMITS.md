# 44. Границы enforcement

## Что это

Протокол istomahandoff — конвенция, записанная в markdown. Этот раздел
фиксирует честно, что конвенция может, а что нет, и какие уровни внешнего
enforcement требуются для каждого класса риска.

## Что защищает конвенция (без внешнего enforcement)

Работает, пока агент добросовестен. Защищает от:

- ошибок и галлюцинаций агента;
- дрейфа автоматичности (постепенного «добора» полномочий);
- context loss и восстановления по памяти;
- самоакцептации и подмены FAIL на PASS;
- случайного выхода за scope;
- формальных чеклистов без содержания.

## Чего конвенция НЕ защищает

- Adversarial-агента (целенаправленно нарушающего правила).
- Prompt injection, когда у агента реальные права на инструменты.
- Скомпрометированную среду (подменённый код агента, чужой процесс).
- Rubber-stamping владельца (частично смягчается docs/46, но не устраняется).

Для этих сценариев требуется внешний sandbox — уровень E2/E3.

## Уровни enforcement

| Уровень | Что реально | Примеры |
| --- | --- | --- |
| E0 CONVENTION | Только markdown-контракт | Свободный чат с агентом без ограничений среды |
| E1 WORKSPACE | Path allowlist, read-only соседние каталоги, запрет destructive tools, нет credentials | IDE с restricted profile, dev-контейнер с монтированием одного каталога |
| E2 SANDBOX | Container/VM, network deny-by-default, seccomp, отсутствие секретов и billing, лимиты ресурсов | Изолированный CI runner, gVisor/Firecracker |
| E3 DUAL CONTROL | Всё E2 + human gate вне агента, signed commits, deploy только через CI с аппроувом | Protected branch + required reviewers + CI-only deployment keys |

## Минимальный E1

Одна именованная команда проверки (компиляция + тесты + рендер/статические
чекеры), запускаемая pre-commit hook'ом. Обход hook фиксируется в evidence.
Переход E0→E1 не требует инфраструктуры — только скрипт и hook в репозитории.

## Минимальный enforcement по risk class

| Класс | Минимум |
| --- | --- |
| R0–R1 | E0 допустим |
| R2–R3 | E1 (для новых зависимостей и сетевых вызовов — E2) |
| R4 | E2 обязателен |
| R5 | E3 обязателен |

Enforcement ниже требуемого — stop condition (docs/33, п. 26).

## Правила

1. Протокол сам себя не enforced. Enforcement существует ВНЕ протокола.
2. Агент обязан заявить фактический enforcement level при первом ответе
   и при его смене. Заявить защиту, которой нет — stop condition.
3. E0 означает: вся защита — конвенция. Владелец принимает решения,
   исходя из этого.
4. Повышение уровня — всегда разрешено. Понижение — owner decision.
5. «Технический enforcement» в других разделах действителен только при
   соответствующем уровне E.
